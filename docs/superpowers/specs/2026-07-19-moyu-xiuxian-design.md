## 1. 背景与目标

### 1.1 为什么做

在 AI 时代，以个人开发者副业形式，打造**可复利的产品资产**（而非纯接单换时间）。

### 1.2 约束

| 项 | 结论 |
|----|------|
| 时间 | 每周约 5–10 小时 |
| 能力 | 全栈，可独立交付可用 Web 产品 |
| 目标 | 可复利资产（引擎可复用、内容可迭代、付费可长线） |
| 用户 | 上班族；利用碎片时间「摸鱼」游玩 |

### 1.3 成功标准（阶段性）

**V1（可玩验证）**

1. 陌生人能在 **10–20 分钟**内完成一段有收获的会话（战斗 / 刷装 / 抽卡至少体验其一，理想三者都沾到）。
2. 核心循环可重复：「布阵过关 → 刷装 → 抽卡改阵 → 再推进」。
3. 不氪金玩家可多试、靠策略通关；付费只提升流畅度（抽卡进度 / 后续体力续航）。
4. 引擎与内容皮肤分离，官方占位剧情可整包替换。

**更长期**

- 有稳定回流（每天少量主动游玩，非挂机）。
- 付费点跑通（先抽卡，后月卡/体力）。
- V2：有限剧情个性化提升粘性与传播。

## 2. 产品定义

### 2.1 一句话

> 面向上班摸鱼的 **Web 文字养成 RPG**：  
> 以**随机装备 + 抽卡定核 + 前后排布阵**推进章节与副本；  
> **每天 10–20 分钟主动玩，不挂机**；  
> 剧情为可替换皮肤（V1 官方默认线；V2 支持 AI 有限个性化）。

### 2.2 参考与边界

| 参考 | 借鉴 | 不借鉴 |
|------|------|--------|
| 《再刷一把 PlayAgain》 | 养成、抽卡、刷装、阵容、爬塔式推进 | Steam 买断形态；过重系统（宠物/符文库等） |
| 《仙剑奇侠传：新的开始》 | 章节节奏、编队策略感、软难度可过关 | 任何仙剑 IP；硬卡池逼氪；重度经营 |
| 国内文字挂机修仙 | 文字低成本呈现 | 挂机收菜主循环、纯数值墙 |

### 2.3 市场判断

- **无高度 1:1 竞品**把「手游养成经济 × 文字皮肤 × 章节剧情 × Web 摸鱼」焊死在一起。
- **赛道本身很卷**（文字修仙 / 挂机很多）。差异化靠：前后排布阵可翻盘、词缀刷装有趣、章节节奏、非挂机碎片体验；宣传需说清「不是又一个挂机」。

### 2.4 版权

- 不可使用仙剑等现成 IP（角色、情节、可识别专有设定、官方资源）。
- 可使用类型 tropes（江湖、师门、情谊抉择等）。
- V1 世界观未定时，使用**占位皮肤**；气质可偏仙侠，内容必须原创或后续 AI 生成原创皮。

## 3. 核心循环与系统分工

### 3.1 主循环

```
推剧情章节 → 解锁更强装备池 / 活动 / 新副本
     ↓
打副本 → 刷词缀与强力装备（「再刷一把」）
     ↓
抽卡 → 提升角色核心能力、改变阵容
     ↓
前后排布阵 / 组合 → 通关剧情与刷本
     ↓
（可选付费）抽卡进度、体力续航 → 更流畅，不锁通关权
```

### 3.2 系统职责

| 系统 | 职责 |
|------|------|
| 剧情章节 | 开门与目标感；解锁更强装备池、活动、新副本 |
| 副本 | 产出不同词缀与强力装备的主渠道 |
| 抽卡 | 提升人物核心能力；带来阵容变化（不只数值） |
| 排兵布阵 | 推进剧情与刷本的主操作；策略可过关 |
| 装备 | 不确定性核心；随机词缀支撑重复刷 |
| 氪金 | 抽卡 +（后置）体力续航 |

### 3.3 设计原则

1. **策略可过关，付费买流畅。** 非硬战力锁下一章。
2. **软难度 + 可重试**：战力不足仍可进战；失败给可读反馈（缺前排 / 缺解控等）。
3. **成长分轨**：抽卡定「会什么」（技能/定位/合击潜力）；装备定「同一角色能刷多高」。
4. **剧情锁内容池，不锁通关资格**：例如通关第 N 章解锁新词缀池，而不是战力不到禁止点下一章。
5. **非挂机**：只有玩家主动游玩才推进进度。
6. **引擎与皮肤分离**：玩法规则与数值框架固定；文案/世界观可替换。

## 4. 战斗系统（V1）

### 4.1 形态

- 前后排：我方最多 **前排 2 + 后排 2**；敌方结构类似（小怪可更少）。
- 前排优先承伤；后排通常不被普通攻击点到，除非敌方有穿透 / 突进 / 群攻。
- 前排被击破后，后排暴露并可能被集火——布阵核心张力。

### 4.2 回合流程（文字呈现）

1. 简短战况（残血、增益/减益）。
2. 为存活角色选择行动：攻击 / 技能 / 防御 / 待命（V1 每角色 1–2 个技能即可）。
3. 结算日志：少量文字讲清因果。

### 4.3 V1 不做

- 复杂多宫格走位、实时操作、连点特效。
- 过重状态机（状态种类控制在可理解范围）。

### 4.4 会话时长目标

- 单场战斗约 **1–3 分钟**。
- 匹配每天 **10–20 分钟**、可拆成 2–3 段短会话。

## 5. 养成与经济（V1）

### 5.1 抽卡

- 优先落地付费点：**抽卡**（角色向）。
- 1 个常驻池 + 保底。
- 新角色应带来**站位/解法变化**（破后排、群奶、反伤盾等），而不只是数值更高。
- 月卡 / 体力付费：**预留接口，后置上线**。

### 5.2 装备

- 槽位：约 **4 槽**（如武器 / 防具 / 饰品等，具体命名随皮肤）。
- 品质：3–4 档。
- 词缀库：约 **12–20 条**；副本产出不同词缀倾向。
- V1 不做完整暗黑级符文库、海量传奇库。

### 5.3 副本

- V1：**2 种**（例如：主线材料本 + 词缀本）。
- 需给玩家「专精刷某本」的理由，避免单一效率本杀死多样性。

### 5.4 体力

- 自然恢复，支撑每天约 10–20 分钟 × 2–3 段。
- 体力是节奏阀，不是惩罚器；免费额度需够完成一段完整刷装体验。
- 付费续航后置。

### 5.5 剧情与进度

- 主线 **6–8 章**；每章约 **3–5 场战斗** + 短过场文案。
- 文案量：服务节奏即可（每章短文），不追求长篇网文。
- V1 可用占位世界观；结构（章节点、战斗、解锁）必须真实可用。

## 6. 用户体验：上班摸鱼

### 6.1 定位话术（草稿）

> 每天 10–20 分钟的文字养成：动脑布阵、刷装抽卡，不挂机。

### 6.2 体验要求

| 要求 | 说明 |
|------|------|
| 打开即续玩 | 尽快回到战斗/副本，减少菜单迷宫 |
| 随时可停 | 单场短；领导经过可快速切走 |
| 界面克制 | 偏工具/文档感，少闪爆全屏动画 |
| 静音默认 | 办公室友好 |
| 进度稳 | 本地存档；可选后续云存档 |
| 一会话有收获 | 10–20 分钟内打完 1–2 场或刷 1 趟本并看到掉落 |

### 6.3 与挂机的区别

- 挂机：上线收菜、离线也涨。
- 本产品：必须主动布阵与决策；离线不推进核心玩法进度（体力自然恢复除外）。

## 7. 技术形态

### 7.1 结论

- **主形态：Web**（可后续 PWA）。
- 原因：目标用户是上班摸鱼 → 浏览器打开即玩；全栈交付最快；文字 UI 包体与实现成本低。
- **不上架优先级：** Steam / 小游戏不作 V1 必选项。微信小游戏可作为验证后的可选分发，非当前主路径。

### 7.2 架构原则

```
战斗结算 ← 阵容 / 站位 / 技能效果 ID
装备生成 ← 词缀表 / 品质 / 副本掉落表
抽卡     ← 池子 / 保底
进度     ← 章节解锁 / 体力
存档     ← 本地（先），账号云存档（后）
内容配置 ← JSON / 表格（剧情与数值外置）
皮肤     ← skinId；文案与显示名可替换
```

- **逻辑与 UI 分离；内容配置化。**
- V1 付费可用测试货币 / 假充值跑通；真支付后置（Web 内购渠道另议：卡密、赞助等）。

### 7.3 建议实现顺序（引擎优先）

1. 数据模型与配置加载  
2. 前后排战斗结算 + 文字日志  
3. 装备生成与穿戴  
4. 副本掉落  
5. 抽卡与角色上阵  
6. 章节进度与解锁  
7. 体力  
8. 官方占位皮肤文案  
9. （后）存档同步、真付费、AI 剧情

## 9. 路线图：AI 有限剧情（V2 想法，已记录）

### 9.1 目标假设

基于用户自己的世界观/走向生成剧情皮，有望提升**部分用户**的粘度与分享欲；  
但**留存主引擎仍是玩法循环**。个性化是加成项，不能替代刷装/布阵/抽卡的爽感。

### 9.2 模式（非完全自由）

- 用户输入期望世界观（可很短）或选择「默认线 / 交给 AI」。
- Skill/AI 按**固定章节骨架与有限选项枚举**生成各章文案与情节包装。
- 游玩中用户可在节点选择走向（2–3 个选项），不跳脱框架。
- 不想管剧情的用户：完全默认线或一键 AI 代选。

### 9.3 约束（防跳脱）

| 锁死（框架） | 可生成（皮肤） |
|--------------|----------------|
| 章结构、战斗场次、解锁、掉落 | 世界名、势力、称呼 |
| 选项槽枚举与 flag | 角色名、对话、过场 |
| 职业/站位/技能效果 ID | 装备与词缀的显示名/描述文案 |
| 数值与规则 | 在允许枝上的情节叙述 |

### 9.4 建议排期

| 阶段 | 内容 |
|------|------|
| V1 | 内容配置化 + `skinId` 预留；仅官方/占位默认线 |
| V1.5 | 开局一句世界观 → 生成并缓存本局皮肤（可选） |
| V2 | 章内有限走向 + 「交给 AI」；注意成本缓存与审核 |

生成策略偏好（待 V2 拍板）：更倾向「开局生成整条线 + 游玩少实时生成」以控成本与稳定性。
