# 系统骨架

> 产品整体骨架：主循环 + 子系统分工。  
> 分系统细则见 [systems/](./systems/)。

## 3. 核心循环与系统骨架

> **整体骨架 = 主循环 + 子系统分工。**  
> 开发按系统拆 plan；战斗验收（§4.11）前不并行铺开养成外壳。

### 3.1 主循环

```
推剧情章节 → 解锁更强装备池 / 活动 / 新副本
     ↓
打副本 → 刷词缀与强力装备（「再刷一把」）
     ↓
抽卡 → 补职能 / 新解法；人物升级抬底子
     ↓
九宫布阵（≤5）→ 自动战斗通关剧情与刷本（可改阵重试）
     ↓
（可选付费）抽卡进度、体力续航 → 更流畅，不锁通关权
```

### 3.3 子系统一览

| # | 系统 | 职责 | 不负责 | 现状 |
|---|------|------|--------|------|
| 1 | **战斗** | 一场内怎么打：出手、索敌、形状、伤害、状态、能量、战报、胜负 | **套装/掉落表/槽位解锁/养成** | 刀一已落地；刀二=驱散/我方混乱/状态补全等**纯战斗** |
| 2 | **布阵** | 九宫站位、出战 ≤5、换人下阵 | 战斗结算 | 已有；UI 可持续打磨 |
| 3 | **人物/卡池** | 卡模板（role/job/技能）、持有列表；**子模块：升级/突破** | 算伤害、随机装 | Demo 池有；成长/抽卡未做 |
| 4 | **装备** | 生成、词缀、穿戴；**套装子模块**；V1 共用衣柜 | 技能解法、副本门锁 | 生成/16 槽露出/`setId` 有；**2/4 效果待副本推进后做** |
| 5 | **副本/遭遇** | 敌阵套路、关卡池；**哪本掉哪套/词缀** | 战斗公式、套装效果定义 | 三套路壳；结构化副本后置 |
| 6 | **章节进度** | 推进、解锁内容池（装/卡/本） | 硬战力锁关 | 未做 |
| 7 | **抽卡** | 获得新卡、补职能加权、保底 | 升级曲线本身 | 未做（门禁后） |
| 8 | **体力** | 每日会话节奏阀 | 战斗规则 | 未做 |
| 9 | **经济/付费** | 货币、抽卡付费、后置月卡/体力 | 通关资格 | 假货币壳 |
| 10 | **故事皮/词表** | `skinId`、显示名、章回包装 | 改 id/公式 | 钩子预留；内容后置 |
| 11 | **存档/会话** | 本地（后云）读写、version bump | 玩法逻辑 | 本地 v2 |

**人物升级归属：** 人物/卡池系统的 **成长子模块**（与「身份」「持有」并列），不是独立一级系统，也不进战斗系统。

### 3.4 成长三轨（已确定）

| 轨 | 系统 | 定什么 |
|----|------|--------|
| 解法轨 | 抽卡 → 人物身份 | **会什么**（职能 + 技能 + 形状特色） |
| 底子轨 | 人物成长（升级/突破） | **底数多高**（主属性等） |
| 强度轨 | 装备 | **同一阵刷多高**（词缀/套装） |

### 3.5 设计原则

1. **策略可过关，付费买流畅。** 非硬战力锁下一章。  
2. **软难度 + 可重试**：战败给可读反馈。  
3. **成长三轨**见 §3.4；V1 装备共用衣柜。  
4. **剧情锁内容池，不锁通关资格。**  
5. **非挂机**：主动玩才推进。  
6. **三层皮肤分离**：规则引擎 / 故事皮 / 卡面皮；战斗认 role + jobId。  
7. **系统边界清晰**：战斗只消费输入；养成与外壳后挂，钩子先留（§4.15–4.16）。

### 3.6 实现顺序（骨架级）

```
① 战斗手感验收 → 战斗刀二（驱散/混乱/状态等，纯战斗）
② 副本结构化（2 种本 / 掉落倾向）← 套装解锁挂这里
③ 装备：套装 2/4 结算 + 更多槽（随推进）
④ 人物池扩 / 成长雏形 → 抽卡
⑤ 体力 + 章节进度
⑥ 故事皮加深 / 真付费
```

细节任务仍见 [tracking.md](./tracking.md)；**拆 plan 时按 §3.3 / §3.7 系统名归档**。

## 代码目录与系统对应

`packages/game-core/src/` 按系统拆目录；对外仍通过 `@moyu/game-core` 聚合导出，web 无需改 import。

| 系统 | 目录 | 主要符号 |
|------|------|----------|
| 共享 | `shared/` | `types`, `rng` |
| 战斗 | `combat/` | `combat`, `targeting`, `ratings`, `mastery`, `lifecycle` |
| 角色 | `character/` | `SKILLS`, `UNIT_TEMPLATES`, `createUnitFromTemplate` |
| 布阵 | `formation/` | `grid`, `DEFAULT_DEPLOYED_IDS`, `buildPlayerParty`, `placeUnit` |
| 装备 | `equipment/` | `AFFIX_DEFS`, `generateEquipment`, `equipItem` |
| 副本 | `dungeon/` | `ENCOUNTERS`, `EnemySpec`, `EncounterDef` |
| 存档 | `save/` | `createInitialPlayer`, `loadOrCreatePlayer`, `grantVictoryLoot` |

依赖方向：`shared` ← 各系统；`character` ← `formation` / `combat` / `dungeon`；`equipment` ← `formation` / `save`；`combat` 不依赖 `save` / web。

Web UI（逐步对齐）：`packages/web/src/features/` — `hub`（布阵）/ `battle` / `inventory`；入口仍 `App.tsx`。
