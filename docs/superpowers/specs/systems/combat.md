## 4. 战斗系统（已确定方向）

> 参考气质：《仙剑奇侠传：新的开始》九宫布阵；**无 IP 内容**。  
> 玩家主操作是**改布阵**，不是每回合点攻击目标。

### 4.1 九宫格站位

我方（敌方镜像）：

```
后排  7  8  9
中排  4  5  6
前排  1  2  3
```

- 格子可空；**出战上限 5 人**（`MAX_PARTY_SIZE`）；Demo 默认 5，池内可有更多卡供换上。
- **前排优先承伤**；前排清空后，中/后排才会被普通攻击点到。
- 穿透 / 刺客类技能：可按规则打到中后排。
- 布阵张力：肉盾靠前、输出/治疗靠后、刺客位决定能否点后排等。
- **群体与形状攻击：** 见 §4.1.1（横排/竖列/全体等）；与具体角色技能绑定，不是笼统「打 3 个」。

#### 4.1.1 九宫目标形状 targetPattern（可扩展）

> 形状由技能 `targetPattern`（**字符串 id**）决定。玩家不点名：先选焦点，再展开形状。  
> **扩展同 `focusPolicy`：** 内置一批；新形状 `registerTargetPattern(id, fn)`，**禁止**写死在战斗主循环。

**格子编号：** 后 789 / 中 456 / 前 123；列左=1/4/7、中=2/5/8、右=3/6/9。

**内置（可增，非封闭终表）：**

| patternId | 中性名 | 命中 |
|-----------|--------|------|
| `single` | 单体 | 焦点 |
| `row_*` / `row_focus` | 横扫排 | 固定排或焦点排；无人则最近有人排 |
| `col_*` / `col_focus` | 贯穿列 | 指定列或焦点列 |
| `all` | 全体 | 该侧全部存活 |
| `cross` | 十字 | 焦点 + 上下左右（无斜角） |

斜角、随机 N、前后两格等：**只注册 + 配技能**。Demo 已用 single / row_front / col_focus；`all`/`cross` 已注册可配卡。

**焦点：** 默认 `lane`；pierce 可打中后排；治疗取残血比最低；`cross`/`row_focus`/`col_focus` 须先有焦点。空集合时 AI 可改普攻。

### 4.2 自动战斗（默认）

- **出手顺序：** 只比 **身法 `spd`**（迟缓可削）；同权则前排 > 中排 > 后排，同排左→右。**急速不参与先手。**
- **索敌（自动 · 用户不点名）：**
  - **默认策略 `lane`（格子对位）：** 同号格 → 同列（普攻前→后 / 穿透后→前）→ 邻列 → 前中后左到右。
  - **破例钩子 `focusPolicy`：** 技能或单位可指定 `lowest_hp` / `front_row` / `backline` / `random` 等；也可用 `registerFocusPolicy(id, fn)` 注册新策略，**不必改战斗主循环**。
  - 解析顺序：`skill.focusPolicy` → `unit.focusPolicy` → `lane`。
  - 治疗：友方 `single` 焦点=气血比例最低者（不对位）；群疗用友方形状（§4.1.1）。
  - 形状技：先按焦点策略选焦点，再按 §4.1.1 展开。
  - **状态例外：** 混乱 / 狂乱仍全场随机（含友军），不走 focusPolicy。
- **用户不指定攻击谁**；对位是默认，破例靠配置/注册钩子。
- 战斗呈现：文字战报滚动；可一键开战看完。

### 4.4 主角与手/自动（已确定）

- 队伍中有且仅有 **1 名主角**。
- 队友：**始终自动**。
- 主角：可切换 **自动 / 手动**。
  - 自动：与队友同一套 AI。
  - 手动：**轮到主角时暂停**，只选 **攻击 / 技能**；**仍不点名目标**（索敌继续自动）。无通用「防御」行动——承伤靠坦克技能/站位。
- 默认状态：主角也自动（最摸鱼）。
- **M2 范围：** 先做九宫 + 全自动（主角暂无开关）。**M3：** 再加主角手/自动开关（按本条粒度）。

### 4.5 实现节奏（已确定 = 选项 C）

### 4.6 V1 / Demo 不做

- 手动点选攻击目标（任何人）。
- 全队每回合逐人点指令（已废弃的旧 Demo 交互）。

### 4.7 会话时长目标

- 单场战斗约 **1–3 分钟**（含布阵）。
- 匹配每天 **10–20 分钟**、可拆成 2–3 段短会话。

### 4.8 属性体系（已确定 · 魔兽结构参考 / 六副属性）

> **设计原则：堆叠即玩法。**  
> 属性堆叠不只是数字变大，而是让角色能力形态分化——同样阵容，因堆装不同，打出来的仗不一样。  
> 结构参考魔兽：主属性定身份 → 副属性常刷取舍（评级→%）→ 稀有词条改风格 → `fortune`/幸运为特殊维。  
> **关键算法已落盘 §4.12。** 下表名为**中性默认显示名**；题材皮见 §2.3.1。

#### 伤害类型 / 力·灵双轴（已拍板 · 2026-07-21）

> **产品结论：双轴必要**（对齐仙剑手游常见「攻击/灵力」取舍，显示名随皮）。  
> **实现状态（2026-07-21）：** 引擎与人物面板已接 `physAtk` / `spiritAtk` / `physDef` / `spiritDef` + 技能 `damageSchool`；旧词缀 `atk`/`def` 读档时并入力系。  
> **后续：** 副本掉落倾向与套装按力/灵分流可再加深。

| 中性默认名 | 字段（建议） | 作用 |
|------------|--------------|------|
| **攻击**（力） | `physAtk` | 力系伤害主系数；普攻默认力系 |
| **灵力** | `spiritAtk` | 灵系技能 / 治疗·护盾主系数（可按技能指定） |
| **防御** | `physDef` | 抵力系承伤 |
| **灵防** | `spiritDef` | 抵灵系承伤 |
| 生命 / 身法 | `maxHp` / `spd` | 不变 |

**技能：** 增加 `damageSchool: 'phys' | 'spirit'`（治疗默认 `spirit`，可覆盖）。  
**结算：** 力伤吃 `physDef`，灵伤吃 `spiritDef`；**终伤 / 暴击 / 急速等副属性仍为共用乘区**（不先拆物暴法暴，降低爆炸复杂度）。  
**迁移：** 旧 `atk`→初始写入 `physAtk` 与 `spiritAtk`（或按 role 偏置）；旧 `def`→双防；存档 bump。  
**克制：** 双轴本身已是「打不对路就疼」；元素/五灵克制仍见后置 **B18b**，**不与双轴绑死**。

> **已废止：** 「V1 永久不分物法/外内」。单轴过渡期已结束（2026-07-21 双轴落地）。

#### 主属性（整数 · 现网双轴）

| 中性名 | 字段 | 直接影响 |
|--------|------|----------|
| **生命** | maxHp | ≤0 下场 |
| **攻击（力）** | physAtk | 力系伤害主系数；普攻默认力系 |
| **灵力** | spiritAtk | 灵系技能 / 治疗·护盾主系数 |
| **防御** | physDef | 抵力系承伤 |
| **灵防** | spiritDef | 抵灵系承伤 |
| **身法** | spd | **先手顺序**；不与急速叠乘 |

面板主区展示攻/灵/防/灵防（或 2×2），身法可留副栏。  
力耐敏智等**主属性转化层**仍更后置（转化 → 本结果层），见 [build-dual-core-design](../2026-07-21-build-dual-core-design.md)。

#### 副属性（六条，常刷；评级 → 百分比 + 软上限）

```
pct = rating / (rating + K)
最终% = min(软上限, pct)
```

| 中性名 | 字段 | 作用 | 软上限 | K |
|--------|------|------|--------|---|
| **暴击** | critRating | 暴击率 | 60% | 80 |
| **暴伤** | critDmgRating | 暴击额外伤害（基础倍率 1.5） | +80%（总约 2.3×） | 100 |
| **急速** | hasteRating | **只加速回能**（gainQi ×(1+急速%)）；**不改先手** | +40% | 90 |
| **均衡** | versRating | 增伤 + 减伤（各一半量级） | 各 20% | 100 |
| **精通** | masteryRating | **按职能**强化本职（§4.8.1） | 等效 ~35% | 90 |
| **终伤** | finalDmgRating | 结算末尾 ×(1+终伤%) | **15%～20%**（最紧） | 120 |

**精通按职能定位：** 见 §4.8.1（下）。  
**副属性取舍说明：** 六条覆盖爆发（暴击/暴伤）、节奏（急速回能）、容错（均衡）、本职（精通）、末乘区（终伤）。命中/穿透等不单开常刷副属性——控制命中走幸运+精通，破甲走状态/特技，避免与现有轴撞车。

### 职能 / 职业 / 初期卡表

> 权威已迁至 **[character.md](./character.md)**（role · job · 出战≤5 · 默认阵容）。  
> 战斗侧只消费上阵单位；精通分支仍按 `role` 结算（§4.12.3）。

#### 稀有词条（低权重，不进常规副属性池）

> 参考魔兽回避链（闪避/格挡分流）与国产养成常见稀有词；**不当副属性主堆**。

| 词条 | 效果 | 存储 | 软上限 |
|------|------|------|--------|
| **闪避** | 受击时有几率**完全免伤**（类似 dodge） | 0~1，**两位小数**（如 0.05） | 0.25 |
| **吸血** | 造成伤害按比例回血（类似 leech） | 两位小数 | 0.12 |
| **抗暴** | **仅降低被暴击率**（不是降被暴伤） | 两位小数 | 0.25 |
| **格挡** | 有几率触发；触发后本次伤害 ×(1−格挡减免)（类似 block：先判定、再减伤，不是免伤） | 触发率两位小数 | 触发率 0.30；减免固定 **0.30** |

没出稀有也能通关；有了是「多一条套路」。  
**数值约定：** 凡战斗用概率/比例字段（稀有词条、派生 % 展示）统一 **两位小数**；副属性**评级**仍为整数。

#### 特殊：幸运 fortune

- 抗控（状态命中 vs 目标 `fortune`）  
- 掉落品质预留（养成期再接）  
- **不当常规副属性堆**；角色底数 + 少量固定来源  

#### 堆叠人格（玩法表达）

| 主堆方向 | 形态 | 战场感觉 |
|----------|------|----------|
| 暴击 + 暴伤 | 爆发流 | 出手一般，暴击削一大截 |
| 急速 | **回能流** | 技能更勤，先手仍看身法 |
| 均衡 | 均衡流 | 能打能抗，容错高 |
| 精通 | 本职流 | 按职能放大（坦/爆发/控/疗…） |
| 终伤 | 终伤流 | 结算末尾抬伤 |
| 闪避 / 吸血 / 抗暴 / 格挡 | 稀有改风格 | 飘忽 / 续航 / 更难吃暴击 / 稳态减伤 |

约束：词条位有限 → 有取舍；单属性软顶 → 鼓励双修；精通按职能 → 同装不同味；阵位仍重要。

#### 伤害 / 治疗 / 状态公式

```
行动顺序 = spd（迟缓可削；急速不参与）
回能 = 基础量 × (1 + hastePct)

原始伤害 = 对应轴攻击 × 技能倍率 × 站位攻修 × (1 + versPct)
暴击：随机() < critRate → 伤害 × critDamage
有效防御 = 对应轴防御 × 站位防修 ×（破甲则 × shredFactor）
防御后 = max(1, 原始 - 有效防御×0.5)
中间 = 防御后 × (1 - versPct) × 坦克精通减伤等（无通用防御姿态）
最终 = max(1, floor(中间 × (1 + finalDmgPct) × 职能输出精通))
受击侧：格挡 → 闪避 → 护盾 → 气血；攻击侧可吸血

治疗量 = spiritAtk × 治疗倍率 × (1 + 治疗向精通%)（不暴击）
护盾量 = spiritAtk × guard 倍率 × (1 + 坦克精通%)（不暴击）

状态命中：随机() < clamp(0.15, 0.95, 0.75 + 控制向精通 - 目标fortune×0.005)
  - 未命中：战报「抵抗」（文案随皮）；附带伤害仍结算
```

- 护盾：优先扣盾，再扣气血。  
- **旧字段迁移：** 门派定位 → §4.8.1；减伤/效果命中 → 均衡 + 坦克/控制精通。  

#### 什么加成什么

| 来源 | 影响 |
|------|------|
| 角色模板 | role + 主属性 + 副属性初始评级 + fortune + maxQi |
| 装备词缀 | 主属性 / 六副属性评级；稀有两位小数 |
| 站位修正 | 前排防 +10%/攻 -5%；后排攻 +10%/防 -5% |
| 技能 | 倍率、tags、applyStatus、qiCost |

#### 职能与属性倾向

| 定位 | 属性倾向 |
|------|----------|
| 全能 | 各项均衡；暴击/急速/均衡都沾一点 |

### 4.9 技能体系（已确定）

#### 技能结构（冻结）

每个角色 V1：**1 个主动 + 普攻**（无通用防御行动；坦克用 `guard`/护盾类招牌技能承伤）。  
**数据结构冻结为：**

| 字段 | 说明 |
|------|------|
| id | 稳定 id |
| nameKey / 默认显示名 | 显示走词表；配置可留默认中文 |
| **targetPattern** | 九宫形状，见 §4.1.1；默认 `single` |
| **tags** | AI 标签：`damage` `pierce` `heal` `guard` `aoe` …（可多选）；`aoe`≈非单体 |
| multiplier | 倍率（群体时对集合内**每人**乘同一倍率；不做距离衰减，V1） |
| **qiCost** | 能量消耗（字段名 `qi`；显示名随皮） |
| **applyStatus** | `{ statusId, chance?, duration?, value?, layers? }[]` — 状态扩展点 |
| **effects** | 可选；非状态类效果列表（见 §4.15.1）。刀一可空，**字段要留** |
| **followUp** | 可选；连击配置（见 §4.9.1）。刀一可不用，**类型要留** |
| aiWeight | 0~1；须能量足够 |

> **禁止**再靠无限新增 `kind` 枚举扩展一切；新状态走 `statusId`，新非状态效果走 `effects[]`。

#### 4.9.1 连击 followUp（规则已定 · 实现可后置）

> 趣味向：差一点翻盘。属**追加打击**，不是暴击、也不是急速多出手。

| 项 | 规则 |
|----|------|
| 触发 | 本次伤害/技能主结算成功后，按 `chance` 掷骰 |
| 次数 | **每行动最多 1 次**（禁止连击再连击） |
| 伤害 | 对追加目标再结算一击，倍率默认 0.4～0.6× 原技能倍率（配置） |
| 形状 | 默认 `single` 打原焦点；可配独立 `targetPattern` |
| 软顶 | 有效连击率建议 ≤0.35（含装备加成后） |
| 战报 | 必须有 event `follow_up`，文案层再喊「连击」 |
| 刀一 | **可不做逻辑**；技能类型预留 `followUp?` 即可 |

#### 能量 qi（冻结）

| 项 | 冻结值 |
|----|--------|
| 上限 | 100（角色底数；V1 装备不堆 maxQi） |
| 开战 | **20**（不够放技能，需普攻攒能） |
| 行动开始 | +5 |
| 普攻后 | +20 |
| 技能消耗 | 40～60（配置） |
| 不足 | 不可放技能 → 普攻 |
| 受击回能 | V1 **不做** |
| 技能 CD | V1 **不做**（能量约束即可） |

#### AI 释放原则

- 先决：`qi >= qiCost`  
- 按 tags：heal / guard / shred / pierce / silence / havoc 等对位择技  
- 不够能量：普攻（坦克靠招牌 `guard`/护盾，不另开防御行动）

### 4.11 阶段门禁：先完成战斗，再养成/章节

> **状态：手感验收已通过（2026-07-21）。** 其后主线见 [tracking.md](../tracking.md)：副本结构化 → 套装 → 抽卡等。  
> 历史纠偏：M1→M2→M3 是战斗**框架**；框架 ≠ 战斗完成。曾要求先把 §4.8–4.10 做实到好玩，再进养成外壳。

**战斗阶段完成标准（已用作验收清单）：**

1. 属性/公式按 §4.8 / §4.12 生效  
2. 能量 qi 按 §4.9；**状态按 §4.13**（破甲/眩晕/护盾 + 混乱或禁疗之一 + 一种 Buff 如暴击提升，可分步）  
3. 初期人物池落地、出战 ≤5；敌人至少三套路，换阵/换状态能感到差异  
4. 战败有一句可读提示（缺破甲 / 被穿透 / 缺治疗 / 可上混乱等）  
5. 堆装方向可感到差异  
6. 状态破阵可感到「可行性」提升（如禁疗掐奶、混乱搅局），不必一次做满全表  
7. 连打多场套路轮换不至于一味无聊  

**验收当时明确不做：** 五行、分职业多资源条、真支付。  
**其后已落地（见 tracking）：** 抽卡 B1、体力 B2、副本 B3；剧情章节仍为 B4。  
**分阶段回顾：** 见 §4.14（验收两刀）。

### 4.12 关键算法（已落盘）

> 玩法意图见 §4.8–4.9；**具体怎么算以本节为准**。改公式先改本节，再改代码与 plan。  
> 参考魔兽思路（评级收益递减、控制递减、期望可解释），不照搬运营级表。短局约 1–3 分钟。

#### 4.12.1 评级 → 百分比

```
pct(rating) = min(cap, rating / (rating + K))
```

| 副属性 | K | cap |
|--------|---|-----|
| 暴击 critRating | 80 | 0.60 |
| 暴伤额外 critDmgRating | 100 | 0.80（加在基础 1.5 上） |
| 急速 hasteRating | 90 | 0.40 |
| 均衡 vers（单侧） | 100 | 0.20（增伤/减伤共用 versPct） |
| 精通 masteryRating | 90 | 0.35 |
| 终伤 finalDmgRating | 120 | 0.18 |

- V1 主属性**不转化**成副属性。  
- 调参：太容易满 → 加大 K 或降 cap；堆了没感觉 → 减小 K。  
- 禁止混用旧「直给减伤%」与均衡双通道。

#### 4.12.2 伤害流水线（顺序锁死）

```
① 行动顺序 = spd（迟缓可削；急速不参与）
② 原始 = 对应轴攻击 × 技能倍率 × 站位攻 × (1 + versPct)
③ 暴击检定 → 命中则 × (1.5 + critDmgExtra)，受目标抗暴修正
④ 有效防御 = 对应轴防御 × 站位防 × shred；防御后 = max(1, 原始 - 有效防御×0.5)
⑤ 中间 = 防御后 × (1 - versPct) × 坦克精通减伤
⑥ 最终 = max(1, floor(中间 × (1 + finalDmgPct) × 输出向精通))
⑦ 受击：格挡 → 闪避 → 护盾 → 气血
⑧ 攻击侧吸血（按实际造成伤害；闪避则 0）
⑨ 回能：gainQi 基础量 × (1 + hastePct)
```

- 护甲：V1 用固定减一段（×0.5），不用魔兽式随等级护甲%；破甲靠降低有效防御体现解法。  
- 治疗/护盾：不暴击、不吃终伤；治疗向/坦克精通分别乘治疗与护盾。

#### 4.12.3 精通（按职能 role）

| role | 算法 |
|------|------|
| flex（全能） | 技能伤 ×(1+m×0.35)；状态命中 +m×0.35；治疗 ×(1+m×0.25) |
| tank | 受伤 ×(1-m×0.8)；护盾 ×(1+m) |
| st_burst | 单体技能伤 ×(1+m×0.85)；穿透 def×m×0.5；暴伤额外 +m×0.1 |
| aoe_dps | 群体技能伤 ×(1+m×0.85) |
| st_ctrl / aoe_ctrl | 状态命中 +m；控类时长 ×(1+m×0.15)（aoe_ctrl 仅群体状态） |
| group_amp | Buff 数值 ×(1+m)；shred 强度微增 |
| st_heal / aoe_heal | 对应单体/群体治疗 ×(1+m) |

#### 4.12.4 控制与负面状态（眩晕）

**定位：** 眩晕是**负面状态（硬控）**，挂在目标 `statuses` 上；与破甲（减益、非硬控）分开。  
参考魔兽 CC diminishing returns：同类控制反复上会变短直至失效。

| 层 | 规则 |
|----|------|
| 命中 | `P = clamp(0.15, 0.95, 0.75 + 控制向精通 - 目标fortune×0.005)` |
| 未命中 | 不挂状态；伤害仍结算；战报「抵抗」（文案随皮） |
| 生效 | 目标跳过行动；`remaining` 按「行动次数」扣减（与现引擎一致） |
| **短局 DR（魔兽式缩时长）** | 对同一目标，在 DR 窗口内（自上次眩晕起目标行动 **6 次** 内，或 18 秒等价用行动近似）：第 1 次满时长 → 第 2 次时长 **×0.5**（至少 1）→ 第 3 次起 **免疫眩晕** 直至窗口结束 |
| 破甲 | **不进**眩晕 DR（减益不是硬控） |
| 场次 | 单施法者每场成功挂眩晕最多 **3 次**（防刷） |
| 不做 | 多类 DR 表（root/fear…）、PVP 韧性、命中等级差 |

#### 4.12.5 几率与公平

**随机源：** Mulberry32 种子；战斗 `seed + turn×1009 + acted×17 + slot`；`game-core` 关键路径不用 `Math.random()`；同种子可复现。

**公平定义：**

1. 期望可解释（面板 30% → 长期约 30%，含抗暴等修正后）  
2. 可复现  
3. 无暗克（不隐藏更低真实 p）  
4. 短局允许方差；用软难度与堆装补，不靠暗改概率  

**V1 战斗内：** 暴击 / 闪避 / 格挡 / 状态命中均为**独立伯努利**。  
**不做：** 战斗内硬保底。暴击 PRD 仅作 §14 B19。

**暴击（含抗暴）：**

```
p = clamp(min(0.6, critRate) - 目标抗暴, 0, 0.95)
crit = rng.next() < p
伤害 *= crit ? (1.5 + critDmgExtra) : 1
```

**受击回避顺序：** 暴击检定（攻）→ **格挡** → **闪避** → 护盾 → 气血 → 状态命中。  
格挡与闪避互斥；禁止一骰多用。

**掉落：** 与战斗分 RNG 流；幸运改掉落权重养成期再接；概率公示见 B13。

#### 4.12.6 能量 qi 节奏

| 时机 | 规则 |
|------|------|
| 行动顺序 | `spd` 降序（急速不参与） |
| 行动开始 | qi += 5（封顶） |
| 普攻后 | qi += 20 |
| 技能 | qi >= qiCost 方可放，成功后扣除 |
| 原则 | 能量是资源不是骰子；急速**只加速回能**（不参与先手、不直接减 qiCost） |

状态完整表见 **§4.13**。

### 4.13 Buff / Debuff（已确定 · 破阵支柱）

> **设计意图：** 状态是破阵与以弱胜强的关键手段，与九宫站位、堆装并列。  
> 目标：低战力可通过正确状态组合（混乱、禁疗、破甲等）提高**过关可行性**，而不是只堆攻击。  
> **参考审视见 §4.13.0**；状态 id 与默认中性名以 §4.13.3–4.13.4 为准。

#### 4.13.0 三款参考审视（2026-07-19）

| 参考 | 值得学 | 别照搬 |
|------|--------|--------|
| 国产回合 RPG（如仙剑系） | **异常少而经典**：晕/默/禁/睡/乱/狂 + 毒；解控成体系；「乱」=不分敌我是破阵王牌；Boss 常免疫硬控 | IP 内容、五行毒差异、道具栏深度、重度操作回合 |
| 大型 MMORPG（如魔兽） | 硬控 **DR**、轻量驱散、减益与爆发窗口 | 几十种 Aura、完整驱散职业战、PVP 韧性表——短局自动战消化不了 |
| 刷装 ARPG（如再刷一把） | **再刷动力在装备/套装/特效**；阵容搭配；状态是调味不是主菜 | 海量装备特效体量；别把状态种类堆到比刷装还复杂 |

**总判断：**

1. **更合适：** 「六异常 + 毒/破甲」做**核心破阵语言**（乱≈混乱，默≈沉默，晕≈眩晕，禁≈禁疗，睡可被打醒，狂=乱打但只普攻且加攻）。  
2. **更合适：** **DR + 轻量驱散**，Boss **分级抗控**（小怪全吃、精英抗部分、Boss 免疫硬控仍吃破甲/毒）。  
3. **更合适：** **套装/饰品特效**常挂短 Buff 或「穿上免控一次」，让刷装改变破阵手段。  
4. **不太合适（从主表降级或合并）：**  
   - **恐惧与眩晕双硬控双 DR** → **恐惧并入 sleep（受伤可醒）**，眩晕保留为 stun（受伤不醒）。  
   - **中毒 + 流血双轨过噪** → **主 DoT 用流血叠层（最多 3）**；中毒简化或不叠层，可后置。  
   - **进攻 Buff 过多** → 保留暴击提升/加攻/加速/命中专注/护盾；暴伤提升与终伤 Buff **合并为「开锋」**。  
   - **完整驱散战** → 只保留 purge/cleanse。  
   - **迷惑 + 混乱并存** → confuse 为弱版；havoc 含友军。V1 可先做 havoc。

**修订后的产品原则：** 状态要「短标能叫出名、有 DR 约束、靠装备放大」——种类服务于破阵可读，不服务于词条收集；**显示名随皮，id 固定**。

#### 4.13.1 分类

| 类 | 说明 |
|----|------|
| **增益 Buff** | 强化己方；提高输出/生存/命中等「可行性」 |
| **减益 Debuff** | 削弱敌方；含 DoT、破甲、禁疗等 |
| **硬控 CC** | 限制行动或技能；走命中 vs 幸运(fortune)，并有 DR |
| **驱散** | 主动移除对方增益或己方减益（轻量驱散战） |

#### 4.13.2 通用规则

1. **同 id：** 默认**刷新时长、数值取新**（不无限叠层）；例外：流血可叠层（见下）。  
2. **时长：** 按**承受者行动次数**扣减（与现引擎一致）。  
3. **命中：** CC / 多数进攻 Debuff：`P = clamp(0.15, 0.95, 0.75 + 控制向精通 - 目标fortune×0.005)`；未中战报「抵抗」（文案随皮），伤害类技能仍可结算伤害。  
4. **己方 Buff：** 默认必中（不掷抵抗）。  
5. **图标/战报：** 挂上、触发、结束、被驱散均有一句可读文案；短标签走词表。  
6. **V1 单单位同时状态软顶：** 最多 **6** 个不同 id（`STATUS_SOFT_CAP`）；超出挤掉最早的非硬控（无 `blocksAct` / `ccDrBucket`），硬控优先保留。

#### 4.13.3 增益 Buff（修订后主表）

少而强，服务可行性；其余靠**装备/套装特效**补花样：

| id | 默认名 | 效果 | 时长 | 备注 |
|----|--------|------|------|------|
| `shield` | 护盾 | 吸收伤害 | 至破 | **已实现**（`appliesAsShield`） |
| ~~`defend`~~ | ~~防御姿态~~ | — | — | **已废止（2026-08-02）**：无通用防御行动；承伤用坦克 `guard`/shield |
| `atk_up` | 加攻 | 攻 ×(1+0.15) | 2～3 动 | **规格预留**；落地须 `registerStatus` |
| `def_up` | 加防 | 防 ×(1+0.20) | 2～3 动 | **规格预留** |
| `crit_up` | 暴击提升 | 暴击率 +0.15（软顶 0.6） | 2～3 动 | **规格预留** |
| `haste_up` | 加速 | 回能倍率临时 ↑ | 2～3 动 | **规格预留** |
| `hit_up` | 命中专注 | 状态命中 +0.12 | 2～3 动 | **规格预留** |
| `open_edge` | **开锋** | 终伤 +0.06 且暴伤额外 +0.10 | 2 动 | **规格预留** |
| `immune_ctrl` | 免控一次 | 免疫硬控 1 次 | 1 次 | **规格预留**；套装/饰品可给 |

**降级为装备特效（不进通用 Buff 主表）：** 单独噬血 Buff、永久镜反等 → 做饰品/套装触发。

#### 4.13.4 减益与异常（机制骨架；显示名随皮）

> 机制参考国产 RPG「定封眠乱狂」分类；**短标签默认用中性字**，题材皮可换成定/封/乱等。

| id | 中性短标 | 默认名 | 类 | 效果 | 破阵定位 |
|----|----------|--------|----|------|----------|
| `stun` | 晕 | 眩晕 | CC | 跳过行动；受击不解除；DR stun | **已实现** |
| `sleep` | 睡 | 沉眠 | CC | 跳过行动；**受伤解除**；DR sleep | **已实现** |
| `silence` | 默 | 沉默 | CC | 不能放技能；DR silence | **已实现** |
| `heal_block` | 禁 | 禁疗 | Debuff | 治疗无效 | **已实现** |
| `havoc` | 乱 | 混乱 | Debuff | 索敌全场随机（含友军） | **已实现** |
| `berserk` | 狂 | 狂乱 | Debuff | 只能普攻，索敌含友军，攻击 ×1.3 | **已实现** |
| `shred` | 破 | 破甲 | Debuff | 防御 × shredFactor | **已实现** |
| `vuln` | 伤 | 易伤 | Debuff | 最终伤害 ×(1+0.15) | **规格预留** |
| `bleed` | 血 | 流血 | DoT | 行动开始掉血；最多 3 层 | **已实现** |
| `poison` | 毒 | 中毒 | DoT | 不叠层；可后置 | **规格预留**（新 tickKind） |
| `slow` | 缓 | 迟缓 | Debuff | **身法** ×0.75（削先手） | **已实现** |
| `confuse` | 惑 | 迷惑 | Debuff | 仅敌对阵营内随机索敌 | **规格预留** |

**现网已注册：** stun、sleep、silence、havoc、berserk、shred、bleed、slow、heal_block、shield。  
**规格预留（须 `registerStatus`，禁止主循环写死 id）：** crit_up、hit_up、atk_up、def_up、haste_up、open_edge、vuln、poison、confuse、immune_ctrl。  
**Boss：** 免疫 stun/sleep/havoc/berserk；仍吃破甲/流血/禁疗/迟缓（见 `StatusDef.rankGate`）。  
**软顶 6 个不同 id：** `STATUS_SOFT_CAP=6` **已落地**（超顶挤掉优先低价值状态）。

#### 4.13.5 混乱 havoc（专项约束）

- **用途：** 对敌方主 C / 治疗上混乱，使其技能可能打到自己人，提高低战力过关可行性。  
- **V1 方向：** 混乱**主要由我方技能施加给敌人**；敌方对玩家上混乱仅限少数遭遇且时长短（防日常关看脸崩盘）。  
- 治疗被混乱：可能奶到敌方（落地选前者，更有戏）。  
- 命中/幸运/场次限制同其他进攻 Debuff；每场对同一目标成功混乱建议 ≤2。

#### 4.13.6 驱散战（轻量）

不做全职业驱散体系，做**可读的驱散对抗**：

| 技能/效果 | 行为 |
|-----------|------|
| `purge` | 驱散目标 **1 个增益**（优先护盾；其余在 `purgeable` 中随机）；显示名随皮 |
| `cleanse` | 驱散己方 **1 个** `cleanseable` 减益；**硬控 stun/sleep/silence 不可净化**（靠自然结束/DR） |
| 套装/饰品 | 可附带概率小净化 |

- 驱散成功必有战报。  
- 能量消耗略低于强力控制技。  
- **可行性：** 高战力靠多层 Buff 时，低战力带 purge 可拆盾拆暴击 Buff，形成「驱散破阵」。

#### 4.13.7 硬控 DR 总览（修订）

| DR 类 | 含 | 规则 |
|-------|----|------|
| stun | 眩晕 | 满 → 半 → 免疫（§4.12.4） |
| sleep | 沉眠 | 同上，独立；**受伤解除**另算 |
| silence | 沉默 | 同上，独立 |

混乱/狂乱/禁疗/破甲**不进**硬控 DR。Boss 免疫见 §4.13.4。

#### 4.13.8 技能 kind 扩展（配置用）

在现有 `damage/pierce/heal/guard/shred/stun` 上增加（可一一对应挂状态）：

`poison` / `bleed` / `slow` / `silence` / `heal_block` / `confuse` / `havoc` / `vuln` / `buff_*`（或统一 `applyStatus` + statusId） / `purge` / `cleanse`

引擎推荐：**技能带 `applyStatus[]`**，比无限膨胀 kind 更干净；kind/tags 保留 AI 用。

#### 4.13.9 与属性/定位的咬合

| 系统 | 关系 |
|------|------|
| 控制向精通 | 进攻 Debuff/CC 命中 |
| `hit_up` Buff | 进一步提高控场可行性 |
| fortune | 抵抗 |
| 急速 vs 迟缓 / 加速 Buff | 节奏对位 |
| 暴击装 vs `crit_up` | 短窗口爆发破阵 |
| 治疗职能 | 净化、治疗；怕禁疗 |
| 套装 | 2/4 件可附带短 Buff 或破甲/混乱 |

#### 4.14.2 战斗验收两刀（纯战斗 · 不含套装）

> **边界：** 战斗系统 = 一场内怎么打。  
> **套装 2/4、掉落表** → [equipment.md](./equipment.md) + [dungeon.md](./dungeon.md)，**不进战斗刀二**（槽位已全开，不再作战斗刀范围）。  
> 战斗只**消费**装备/套装已经算好的数值与进战 Buff。

| 刀 | 范围（仅战斗） |
|----|----------------|
| **刀一** | 六副属性结算 + qi + §4.10 技能状态 + 敌方 stun/slow + heal_block 或 havoc 之一 + 伤害链 + 形状；装备侧仅「能穿上加成」（套装效果可不激活） |
| **刀二** | **驱散** purge/cleanse、**玩家可施加 havoc**、状态补全（sleep/berserk 等）、形状卡补全（如 `col_focus` 贯穿列）、抗控/DR 体验打磨 |

**刀一玩家必覆盖（按人物表职能）：** 坦克护盾、单体爆发（流血/穿透）、群体攻击、单体控制（沉默）、单体治疗、全能输出。  
**刀一敌方必覆盖：** stun；slow；heal_block 与 havoc 至少一种。  
**role 枚举冻结：** `flex|tank|st_burst|aoe_dps|st_ctrl|aoe_ctrl|group_amp|st_heal|aoe_heal`。

#### 4.14.3 抗控分级

| 对象 | stun/sleep/havoc/berserk | silence | 破甲/流血/禁疗/迟缓 |
|------|--------------------------|---------|---------------------|
| 小怪 | 全吃 | 全吃 | 全吃 |
| 精英 | 抗 sleep/havoc 或时长减半 | 全吃 | 全吃 |
| Boss | **免疫** | 可吃（缩短） | 全吃 |

#### 4.14.4 战斗状态机（骨架）

```
Hub 布阵/装备 → CreateBattle
  → RoundLoop（按身法 spd）
      → 跳过：dead / stun / sleep（sleep 受伤可醒）→ 主角手动可暂停
      → 行动开始：qi+5；DoT；emit turn_start
      → 择技 → 结算（含形状展开）→ 可选 followUp
      → emit 事件钩（on_hit / on_kill / on_block…）→ 判胜负
  → 回合推进
→ Won 掉落 / Lost 提示 → Result
```

> 单位生命周期与胜负条件见 **§4.15.1**（为复活等后置能力留钩）。

#### 4.14.5 掉落管线（骨架）

胜利 → 交给**装备/副本**掉落管线生成 1 件（槽位权重、setId、本源倾向见装备与副本文档）。战斗本身不定义套装效果。

#### 4.14.6 战中 UI

异常 **短标签**（走词表）；能量短条/数字；副属性卡片只露 2～3 个关键 %。

#### 4.14.7 何谓翻案

- **可调：** K、软上限、qi 数字、词缀区间、倍率。  
- **翻案先改文档：** 槽位露出、分柜、伤害顺序、状态 id、qi 结构、`applyStatus` 模型、词表 schema。

#### 4.15.1 扩展钩子（现在留口 · 逻辑可后置）

> 回答：「现在不做，以后加会不会很麻烦？」——**钩子留对了就不麻烦；写死了就大改。**

##### A. 单位生命周期（复活 / 召唤 / 换人 级）

| 钩子 | 要求 | 刀一 | 以后解锁例 |
|------|------|------|------------|
| 单位不物理删 | `hp<=0` → 标记 `dead`（或 `downed`），**仍留在阵上格子**；移出行动队列即可 | 至少 `dead` 标志，勿 `splice` 没痕迹 | 复活读格子把人拉回 |
| 胜负条件软判定 | **败：** 己方 `可被选为行动者的存活单位 == 0`；**胜：** 敌方同理。不要写「数组长度变 0」绑死 | 用「存活且非 dead」计数 | 复活、召唤物 |
| 行动资格 | `canAct = alive && !stun && !sleep && …` 集中一处 | 一函数 | 免控、混乱只普攻 |
| 复活 effect | `effects` 预留 kind：`revive`（hp 比例、是否清状态、当回合能否动） | **枚举占位，不实现** | 治疗大招复活 |

##### B. 技能效果管道（连击 / 斩杀赏 / 非状态效果）

| 钩子 | 要求 | 刀一 | 以后解锁例 |
|------|------|------|------------|
| 结算阶段固定 | `选目标 → 主效果 → applyStatus → followUp? → 钩子事件 → 胜负` | 阶段顺序写清 | 插反击、斩杀回能 |
| `effects[]` | 非 Buff 类：`damage` `heal` `shield` `revive` `purge` `cleanse` `grant_qi`… | 刀一只用 damage/heal/shield；**类型联合要可扩** | 复活、驱散、回能 |
| `followUp?` | 见 §4.9.1 | 类型预留 | 刺客连击 |
| **`focusPolicy?`** | 单体伤害焦点策略 id；默认 `lane`；`registerFocusPolicy` 可扩 | **类型 + 注册表已留**；Demo 全用默认 | 斩杀锁残血、嘲讽、必打后排 |
| 禁止 | `switch(skill.kind)` 无穷膨胀当唯一扩展方式 | tags + effects + status + focusPolicy | |

##### C. 战斗事件总线（概率甜头 / 战报 / 成就）

刀一就要 `emit(code, payload)`，即便暂时只有战报订阅：

| event code | 何时 | 后置可挂 |
|------------|------|----------|
| `turn_start` | 行动开始 | DoT 已有；以后挂先手气势 |
| `hit` / `crit` / `resist` | 命中结算 | 会心追击 |
| `status_apply` / `status_block` | 上状态 | 破甲赏 |
| `unit_down` | 进 dead | 斩杀回能、击杀计数 |
| `unit_revive` | 复活成功 | 战报 |
| `block` / `dodge` | 减免链 | 格挡反击 |
| `follow_up` | 连击 | 文案 |
| `battle_end` | 胜负 | 差一口气评价、再战气势 |

> UI/战报**只消费事件**，不在结算函数里拼死中文句子。

##### D. 配置与内容钩子

| 钩子 | 要求 |
|------|------|
| 卡 = `role` + `jobId` + `skillId` | 新趣味多半是**新配置**不是改引擎 |
| 形状 / 状态 / job **可扩：形状与焦点走注册表；状态走 statusId；job 有表可增** | 新加先改规格再改代码；禁止主循环无限 switch |
| 装备 `setId` + 特效表后置 | 刀一掉落可带 setId，效果表可空 |

##### E. 明确「后加也贵、现在不必留复杂实现」的

| 项 | 说明 |
|----|------|
| 分柜装备、点名目标、联机 | 不留半吊子实现；维持「不做」 |
| 力·灵双防（双轴） | **已落地**；字段与结算勿半吊子回退单轴 |
| 完整召唤军团 / 多队伍 | 仅单位生命周期钩子够用；不做召唤 UI |
| 复活数值与次数 | 后置再定；现在只留 effect 与 dead 态 |

##### F. 自检（刀一 PR 用）

实现刀一时对照：

1. 有没有把死人从数组删到无法引用？  
2. 胜负是不是只认「存活可行动」？  
3. 技能能不能在不改引擎核心的情况下多一个 `effects` kind？  
4. 战报能不能只靠 event code 渲染？  
5. `followUp` / `revive` 是否已在类型里（哪怕 never 用）？  

满足则：连击、复活、斩杀回能、格挡反击等**后加主要是内容 + 小段结算器**，不是翻战斗循环。

#### 4.15.2 可扩展清单 vs 宜冻结（Buff / 效果 / 内容）

> 回答：「以后还要加什么，现在哪里不能写死？」——**能登记的走注册表；管道阶段与字段名宜稳。**

##### 可后加（数据 / `register*`，禁止主循环硬编码新 id）

| 类别 | 怎么加 | 现网钩子 | 后续可能例 |
|------|--------|----------|------------|
| **Buff / Debuff / CC** | `registerStatus({ id, flags… })` + 技能 `applyStatus` | `StatusDef`：`blocksAct` / `blocksSkill` / `forceRandomTarget` / `forceBasicAttack` / `wakeOnDamage` / `healBlocked` / `purgeable` / `cleanseable` / `ccDrBucket` / `tickKind` / `outgoingDamageMult` / `actionWeightMult` / `incomingDefMultFromValue` / `maxBattleApplies` / `stack` / `appliesAsShield` / `rankGate` | 冰冻、嘲讽、护盾易伤、DOT 毒、减暴击、增疗 |
| **目标形状** | `registerTargetPattern` | `TargetPattern = string` | 菱形、邻格、随机 N |
| **焦点策略** | `registerFocusPolicy` | `FocusPolicyId = string` | 嘲讽锁、斩杀残血 |
| **非状态效果** | `registerSkillEffect(kind, handler)` + 技能 `effects[]` | 内置 purge / cleanse / grant_qi | revive、steal_qi、redirect |
| **状态跳字 DoT** | `registerStatusTick(kind, handler)` + `StatusDef.tickKind` | 内置 `bleed_hp_pct` | 毒、燃、回复跳字 |
| **战报事件** | 新 `emit(code)`；UI 只认 code | §4.15.1 C | 击杀赏、套装触发 |
| **词表 / 皮** | `t(key)` + skin | status/job/skill nameKey | 新题材皮 |
| **套装 / 词缀** | 表驱动；进战短 Buff 挂 `applyStatus` | 装备 effects 后置 | 2/4 件套 |
| **副本 / 掉落** | 遭遇表 + 掉落表 | encounters | 新本分流 |

**加新状态的正确路径：** 登记 `StatusDef`（行为用 flag）→ 技能/词缀引用 `statusId` → 测抗性/DR/驱散。**不要**在 `combat.ts` 写 `if (id === '新状态')`。

**若现有 flag 盖不住新行为：** 先扩 `StatusDef` 一个语义清晰的 flag（或 `tickKind` 新值 + 通用 tick 表），再实现**通用**读取；仍禁止只为某一个 id 开特例分支。

##### 现网诚实缺口（勿当已完成）

| 缺口 | 说明 |
|------|------|
| 词表 / skin | 技能有 `nameKey`；UI 角标已读 `statusLabel`；色调 map / core `formatEvent` 中文仍 Demo 级 |
| 升星 `StarNodeEffect` | 仍为封闭联合；后置可改 string + 注册 |
| 配置外置 | 卡/技能/状态现写在 TS；以后可迁表，接口保持 register |

**已收口（2026-07-22）：** `registerSkillEffect` / `registerStatusTick` / 状态软顶 `STATUS_SOFT_CAP`；新 effect/tick 禁止回主循环写 if。

##### 宜冻结（改晚极贵）

| 项 | 说明 |
|----|------|
| 行动管道阶段顺序 | 资格 → turn_start → 择技 → 目标 → 主效果 → applyStatus → followUp → 胜负 |
| 伤害流水线阶段 | 暴击检定 → 格挡 → 闪避 → 护盾 → 气血（与 §4.12.5 一致）；可调系数，勿插乱序 |
| 力·灵双轴字段 | `physAtk` / `spiritAtk` / `physDef` / `spiritDef` + `damageSchool` |
| 先手 vs 急速 | 先手只 `spd`；急速只加速回能 |
| 单位不 splice、胜负认存活 | 复活/召唤前提 |
| 稳定 event code 名 | 可增，勿改旧 code 语义 |
| 存档字段名 / 槽位结构 | 可空扩展；勿改义 |

##### 后置可加、现在不必实现（钩子已够）

冰冻/石化、嘲讽、反击、斩杀回能、复活、召唤、套装进战 Buff、更多 DOT tickKind、共享 DR 桶的新硬控、付费抽卡升星质变技能——**以配置 + 注册为主**，不是新开战斗子系统。

### 4.16 生命周期架构（已确定 · 总图）

> **结论：** 战斗向架构 = **几条生命周期 + 固定阶段管道 + 事件钩子 + 数据驱动内容**。  
> 钩子留对 → 趣味/职业/复活后加不掀桌；公式与交互模式写死 → 才会大改。  
> 本节是 §4.14 / §4.15.1 的总览；实现以本节阶段名为准。

#### 4.16.1 五条生命周期

```
① 会话 Session
   Hub → 布阵/装备 → CreateBattle → (战斗循环) → Result/掉落 → 回 Hub

② 战斗 Battle
   创建双方单位 → 行动队列循环 → battle_end(胜/负)

③ 行动 Action（管道，顺序锁死）
   资格检查(canAct)
   → turn_start（qi+5、DoT、emit）
   → 择技（自动/主角手动）
   → 解析 targetPattern → 目标集合
   → 主 effects（damage/heal/shield…）
   → applyStatus[]
   → followUp?（预留）
   → emit（hit/kill/block…）
   → 胜负检查

④ 单位 Unit
   入场(alive) → 可行动 ↔ 控制跳过
   → hp<=0 则 dead（保留格子与引用）
   → [后置] revive → 再入可行动
   → 离场（战斗结束清理）

⑤ 内容 Content（非运行时，但同属架构）
   卡(role+jobId+skillId) / 状态表 / 形状枚举 / 词表 skin
   → 只改配置扩玩法；引擎认 id
```

#### 4.16.2 架构原则（四句）

1. **阶段固定，钩子开口** — 管道步骤不随意插队；新逻辑挂事件或新 effect kind。  
2. **内容后挂** — 新职业/连击/形状卡优先加 JSON/表，不改核心循环。  
3. **逻辑与文案分离** — core 只 emit code；UI `t()` / 战报模板。  
4. **死人可引用** — 生命周期完整，复活才接得上。

#### 4.16.3 刀一必须落地的架构件

| 件 | 验收 |
|----|------|
| Unit.`dead` + 仍在 party 数组 | 击倒不 splice 丢引用 |
| `canAct(unit)` / `livingSide(side)` | 胜负与行动共用 |
| Skill：`targetPattern` + `applyStatus` + `effects?` + `followUp?` + `focusPolicy?` | 类型可扩 |
| `BattleEvent[]` 或等价 emit | 战报只消费事件 |
| 伤害链顺序 §4.12.2 | 单测锁顺序 |
| 形状至少 `single` / `row_front` / `col_focus` | Demo 法师横扫前排 |
| qi 节奏 §4.9 | 开战 20 / +5 / 普攻+20 / 技能耗 |

#### 4.16.4 审视结论（开工前）

| 项 | 状态 |
|----|------|
| 九宫 / 自动 / 手自动框架 | 已有代码，刀一升级内容 |
| 属性 / qi / 状态 / 形状 / 职业 | 规格已收口 |
| 生命周期与钩子 | §4.16 已定 |
| 细规则缺口（穿透焦点权重等） | 实现期按 §4.1.1 常识补，不挡开工 |
| 战斗不做 / 外置 | **套装定义与 2/4 效果**（装备）、**按本掉落**（副本）、分柜、AI 皮 |
| 刀一可不做 | 驱散、连击逻辑、复活逻辑（钩子已留） |
| 刀二已落地 | purge/cleanse、玩家 havoc、sleep/berserk、`col_focus` 卡、DR/抗控分级 |

**刀一 / 刀二（纯战斗）均可验收；套装与按本掉落见装备/副本系统。**
